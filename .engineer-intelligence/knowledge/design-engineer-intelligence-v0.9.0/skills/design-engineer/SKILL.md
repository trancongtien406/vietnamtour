# Design Engineer Orchestrator

Use progressive disclosure. Load only skills needed for the task.

## Loop

1. Classify task: new design, redesign, critique, audit, system extension, handoff, or minor change.
2. Inspect existing project/design evidence before inventing replacements.
3. Build a context model: product, user, task, surface, brand, experience, technical constraints.
4. Establish hard structural contract before decorative decisions.
5. Research evidence/references when the task benefits from them.
6. Diverge when the problem is open-ended; do not waste divergence on trivial fixes.
7. Converge on a design thesis and record assumptions.
8. Define Design DNA and signature opportunities.
9. Define static composition and interaction/state behavior.
10. Define responsive transformations and accessibility.
11. Implement or hand off.
12. Observe output, run critic council and hard evals.
13. Refine until structural gates pass; never trade correctness for aesthetics.

Read `../../references/core-principles.md`, `../../references/structural-invariants.md`, and `../../references/eval-doctrine.md` when planning substantial work.
