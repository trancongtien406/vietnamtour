# Visual Experience Doctrine

## Prime rule

A visual element must earn its presence.

Use visual assets when they improve:

- comprehension;
- hierarchy;
- discoverability;
- feedback;
- identity;
- atmosphere;
- continuity;
- trust;
- task confidence.

Do not add them merely because the interface has empty space.

## Asset-aware implementation

Treat meaningful assets as real feature dependencies.

A screen can depend on:

```text
logic
data
components
content
icons
imagery
illustrations
thumbnails
characters
motion
sound
```

Do not silently downgrade an asset-dependent experience into placeholder text
and generic cards.

## Visual semantics before decoration

Prefer:

```text
visual → communicates a concept/state/action
```

over:

```text
visual → fills space
```

## Reuse before generation

Priority:

1. approved project asset;
2. approved design-system asset;
3. established icon / media source already used by the project;
4. deterministic vector / code-native graphic;
5. generated visual asset;
6. new runtime visual dependency only when justified.

## Existing project truth wins

If a repository already has icon rules, art direction, illustration style,
photography style, mascot rules, game-world metrics, asset manifests, or motion
tokens, reuse them instead of inventing a competing system.

## Fidelity is not sameness

Consistency means shared visual DNA, not duplicated composition.

Maintain:

- visual weight;
- perspective;
- lighting logic;
- line / shape language;
- palette relationships;
- density;
- scale system;
- motion personality.

Allow:

- compositional variation;
- expressive variation;
- task-specific art;
- different visual emphasis;
- different layouts.

## No generic AI finish

Never treat these as sufficient by default:

- rounded card + icon + title + description repeated everywhere;
- one generic icon per feature as the entire visual language;
- random gradients added to imply premium;
- emojis used as final product art without product intent;
- stock photos added without a role;
- generated illustration that does not match the surrounding system;
- image assets containing accidental text;
- visual placeholders left in final output.
