# Eval doctrine

Evaluate behavior and decision quality, not resemblance to a preferred screenshot.

## Structural pass/fail

- navigation available at every target state;
- shell geometry remains valid;
- desktop collapsed state and mobile drawer state are distinct where both exist;
- focus/keyboard behavior valid;
- explicit scroll ownership;
- no accidental page overflow;
- content transforms appropriately;
- reduced motion/accessibility considered.

## Quality dimensions

- product relevance;
- hierarchy;
- coherence;
- usability;
- clarity;
- accessibility;
- responsiveness;
- originality;
- technical feasibility;
- consistency with existing system.

## Diversity eval

Run the same open-ended brief multiple times. Compare design thesis, composition, typography strategy, interaction model, metaphor and signature behavior. Cosmetic color variation does not count as diversity.

## Blind comparison

Hide version identity from the comparator. Compare outputs on the same rubric and analyze why one succeeds. Do not ask the comparator to select the design that most resembles a stored reference.
