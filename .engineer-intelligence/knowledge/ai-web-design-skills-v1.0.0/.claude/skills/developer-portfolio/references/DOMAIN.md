# Developer / Engineer Portfolio Domain Model

## Subtypes

- mobile engineer
- frontend engineer
- backend engineer
- full-stack
- freelancer
- technical studio

## Primary audiences

- hiring managers
- founders
- clients
- engineering peers

## Common conversions

- view projects
- understand expertise
- contact/hire
- read technical writing

## Trust signals

- real projects
- architecture decisions
- outcomes
- code/GitHub when useful
- clear role on projects

## Discovery questions for the agent

- Which subtype is this?
- Who makes the purchase/decision?
- Is the site primarily discovery, evaluation, transaction, booking, or lead generation?
- What proof exists and what must not be fabricated?
- What content/media is actually available?
- What industry cliché should be deliberately avoided?
